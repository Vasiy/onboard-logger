Fault codes (DTC)

        
Requires a live ECU connection (Logger tab must show “connected”). Not available during a Full parameter scan.

        
Diagnostic session: not started — started automatically on the first test (83 03 00 FF 00 FF 00 + 10 81).

        

          
          
          
        

        

        
What this does
          
Read fault codes — Reads stored/current diagnostic trouble codes (SAE code + status) via ReadDTCByStatus 18 00 FF 00. Read-only, changes nothing.

          
Clear fault codes — Erases stored DTCs from ECU memory via ClearDiagnosticInformation 14 FF 00. Codes reappear if the fault is still present. Does not touch adaptations, tuning or firmware.

        

      

      

        
Adaptation resets

        
⚠ Engine OFF (kill-switch), ignition ON. Verified for the IAW 5AM.

        

          
          

            

            
—

          

          
        

        

        
What this does
          
Reset TPS — Resets the throttle-position adaptation (closed-throttle reference) via StartRoutine 31 21. Do it engine-off / ignition-on; the ECU relearns idle afterwards.

          
Reset self-adaptation — Clears the ECU self-learned fuel/idle adaptation (Selbstadaption) via 30 7E 04. The ECU relearns over the next rides.

        

      

      

        
Actuator tests

        
⚠ Engine OFF (kill-switch), ignition ON. Each button energizes a real output (fuel/spark/pump) for a moment, then auto-off. Confirm each.

          Scan
          

            
            
            
          

        

        

          
Sweeps 0x21 <rli> 0x00–0xFF (both framings), logs scan-*.ndjson + wide CSV. Run with the engine idling, blip the throttle. Finds every readable rli.

Clock

            

              

                
Board time—

                
This device—

              

              
            

            
            

              
Clock source

              

                
                
              

            

            
            
The board has no battery-backed clock. With this on, the first browser that opens the UI after a power-up sets the date, time and timezone — once per power-up, and only if the two clocks differ by more than 2 s.

            
            
—

          


          
          

            
Processor
              —
            

            

              
              
            

            
The load never reaches one core, so a lower ceiling costs nothing measurable and keeps the board further from the temperature at which the kernel starts cutting the clock on its own. An empty value leaves the kernel default alone. The setting is re-applied on every boot.

          

          
          

            
Power save

            
            

              
              
            

            

              
              
            

            
With the ignition off the board keeps looking for the ECU every two seconds and drains the battery. The first step drops the processor to its lowest speed; the second powers the board off, and needs the ignition turned on again. Both are cancelled the moment the ECU answers. The poweroff waits while a browser has this page open, while a firmware operation or a scan runs, and while a ride log is being written — the slow-down never waits for anything.

          

          
          

            
Fan
              —
            

            
            

              
              
              
            

            
2: temperature only, no tach. 3: tach shares the 2-pin connector's own chopped power — only accurate at 100% duty. 4: dedicated PWM + tach line — accurate at any duty.

            

            
            
            
          

          
          

            
Log storage
              —
            

            

            

            
Where every log the board writes goes — rides, the board's own diagnostics, and the firmware and update logs — into a folder per day. Pick a USB drive and they go to it instead of the board's card; if it is not plugged in when recording starts, the board falls back to internal memory so a ride is never lost.

          


          
          

            
Update
              —
            

            
Build the archive on the dev host with ./release.sh, download it to this device and pick it here. The board checks the archive, runs its own offline test suite and only then swaps the code in — and puts the old version back by itself if the new one does not come up.

Add-ons

            
An add-on adds a page to this board — the ECU map viewer, for instance, which draws the firmware images stored here. It is content only: nothing in it runs on the board. It keeps its own files beside it, and removing it takes them with it.

            

              
            

            

            

          


          

            
Board logs
              
            

            
            

              
              
            

            
Records USB, Wi-Fi and K-Line events next to the ride logs: what the kernel says about the adapter, when the link came up or died, and a board snapshot every few seconds. On reaching the limit the file is archived to .zip and a new one starts. The files are listed right below; /api/diag.txt opens the current one as plain text.

            

              

                
                
                
                
              

              
            

            

              
              
            

            

              
              
              
              
            

            

            
Two kinds live here, both written by the board rather than by a ride: the diagnostics log (deb) and one file per firmware read or write (fw). Opening a row shows it as text; a .zip is a download only.
