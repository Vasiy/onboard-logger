# Onboard Logger — рабочий статус (handoff для нового чата)

Прочитай этот файл первым. Он держит состояние проекта, чтобы продолжить без старого контекста.

## Что за проект
Бортовой K-Line логгер для мотоцикла с ECU **Magneti Marelli IAW 5AM (HW610)** на
**NanoPi NEO3** (Ubuntu 24.04, RK3328). Плата поднимает Wi-Fi AP «nano loger» +
веб-UI (FastAPI), коннектится к ECU по KWP2000/ISO 14230, пишет логи, читает/пишет
прошивку. GitHub: публичный `Vasiy/onboard-logger` (открыт для тестирования).

- **Доступ к плате**: адрес и пароль — в `.deploy.env` рядом с чекаутом (не в git). Репозиторий
  публичный, поэтому учётные данные в него не пишем: ни в доках, ни в скриптах, ни в примерах.
- **Деплой**: `./deploy.sh` с dev-хоста (весь репозиторий, не только `app/`; прогоняет тесты,
  перезапускает сервис и сверяет контрольные суммы в обе стороны, падая при любом расхождении).
  Флаги: `--no-tests`, переменные `BOARD_HOST`, `BOARD_USER`, `BOARD_PASS`, `PY` — либо те же ключи
  в `.deploy.env`, который скрипт подхватывает сам.
  **Любое изменение обязано доехать до платы** — на плате нет git, там лежит только последний rsync.
  Конфиг на плате: `/etc/onboard-logger/{config.json,params.json,ecu_id.json,fw_catalog.json}`.
  Логи ECU: `/root/k-line/`.
- **Тесты/проверки** (dev-хост, venv `.venv`): `.venv/bin/python tests/test_kline.py` (20 шт; вся папка tests/: 130 шт); `.venv/bin/python -c "import app.main"`; `node -e "new Function(require('fs').readFileSync('app/static/app.js','utf8'))"`; i18n-паритет — все 8 локалей равны (сейчас **324 ключа ×8**).
- CAVEMAN MODE активен (см. стиль), отвечать **по-русски**. Git-коммиты только по просьбе.

## Реверс IAWDiag_V0.52 (ключевые факты; файл декомпайла лежит у пользователя вне репозитория)
- Кадр: `[0x80|len][0x10][0xF1][data][cs=Σ&0xFF]`; ответ `[..][0xF1][0x10][data][cs]`. Короткий кадр без адреса (fmt0): `[len][data][cs]`. `sub_407F47` строит, `sub_45973E` принимает.
- **Live-init** (диаг): fast-init (BREAK 25мс low+25мс high) ИЛИ 5-baud slow-init → `81` StartCommunication → **poll по одному параметру** `21 <rli>` (значение из `data[1..2]`, 16-бит; RPM=`15000000/period`) → TesterPresent `3E` /3с → StopComm `82`. НЕТ `10 85` и `1A` для live.
- **Measurement-rli лежат в `0x30..0x7F`** (НЕ rli=1 → тот даёт NRC 0x12). IAWDiag диспетчер параметров = `sub_432586` (индекс→геттер).
- **Testing-команды**: ReadDTC `18 00 FF 00` (ответ `58 <count> [hi lo status]*`, DTC по SAE J2012), ClearDTC `14 FF 00`, StartRoutine `31 <id>` (сбросы, напр. `31 21`/`31 23`), IOControl `30 <id> 07/00` (актуаторы on/off).
- **Метки IAWDiag не резолвятся** — UI-текст грузится из внешнего файла локализации (в .exe только ключи `Settings_N`,`Fault_N`,`O1..O4`). Поэтому какой `31 <id>`=Reset TPS и id актуаторов для 5AM — **не верифицированы**. Firmware-путь (для 5am_util): `10 85`→`27` seed/key→смена baud→`34`/`36`.
- Эталон каналов 5AM (из `GuzziDiag_V0.60_...csv` этого мота): RPM, Voltage, Injection period, Engine temperature (21→81 прогрев — лучший маркер), Throttle, Air pressure, CO Trimm, Stepper. ECU отдаёт **больше** (напр. 2 лямбды).

## Архитектура (что где)
- `app/kline/transport.py` — serial + fast-init + framing. `build_frame(data, with_addr=True)`, `recv_frame(timeout=None)`.
- `app/kline/kwp2000.py` — `KWP2000Session`. `connect()` (без 0x10), `read_local(rli, with_addr, timeout)` (зонд `21 rli`, не падает на NRC/timeout, отдаёт dict {status,tx,rx,data,val16,nrc}), `read_dtc()`, `clear_dtc()`, `_dtc_code(hi,lo)`.
- `app/kline/params.py` — per-param схема: `Param{key,name,rli,fmt(2/0),offset(1),length,endian,signed,scale,bias,recip,digits}`, `ParamMap{poll_interval_ms,poll_timeout_ms,params}`. Legacy-блок авто-конвертится.
- `app/kline/logger.py` — `KLineWorker` (поток). Per-param poll (кэш по rli), **scan-режим** (`_scan_loop`: sweep 0x00..0xFF both, лог `scan-*.ndjson`+широкий `scan-*.csv`, 1-й проход весь диапазон затем только живые; авто-стоп по таймеру; прогресс по rli), **command-executor** (`run_command`/`_exec_command` для Testing на worker-потоке), взаимоисключение scan↔логи.
- `app/main.py` — FastAPI. Эндпоинты: `/api/state`, `/ws` (0.2с снапшоты), `/api/logging`, `/api/selected`, `/api/kline/scan` (on/start/end/fmt/duration), `/api/testing/{read_dtc|clear_dtc}` (sync→threadpool, гард connected+не scan), firmware/*, logs/*, config.
- `app/web/state.py` — снапшот (values, scan_*, log_*, catalog, ecu_*). `app/web/config_mgr.py` — сеть/hostapd/dnsmasq.
- `app/static/{index.html,app.js,style.css,i18n.js}` — SPA. Табы: Logger, Firmware, **Testing**(перед Config), K-Line logs, Config. i18n 8 локалей (En default).
- `config/params.json` — **ГОТОВО: верифицированная карта 5AM** (79 rli 0x30..0x7F, fmt2, offset=2). Ответ ECU = `61 <rli> <value>`, значение с offset 2 (после SID+эхо rli), big-endian, длина 1/2/3 байта по rli. Именованы 12 каналов с формулами из GuzziDiag v0.42 reverse (см. ниже), остальные — raw `rli 0xNN`.

## Что сделано (полностью)
Логгер+AP+2 потока логов, firmware read/write (5am_util), charts/sparklines, live bus-speed, friendly errors, per-param poll, **Full parameter scan** (отдельный тумблер на Logger, авто-стоп 2/3/5мин/∞, прогресс «проход 1: %(0xNN/0xFF)» + countdown, авто-возврат лог-тумблеров), взаимоисключение scan↔логи, **вкладка Testing** (Read/Clear fault codes с аннотациями). UI 2026-08-22: TPS-прогрессбар между кнопками Reset TPS и Reset self-adaptation (шкала фиксированная 0–90°, под баром по центру `X.X° · NN %`, обновляется только пока вкладка Testing открыта; если `throttle` не отмечен на Logger — «—» и подсказка в тултипе). Блок Scan вынесен отдельной приглушённой карточкой в самый низ вкладки Logger: в покое видны только заголовок, auto-stop, frame и тумблер; прогресс, метки событий и пояснения разворачиваются (`#scanBody`) только на время скана, карточка подсвечивается акцентом.

## UI-проход 2026-08-25/26 (деплой на плату сделан)
- **Обратная связь**: свои `toast()` и `confirmDialog()` вместо всех нативных `alert`/`confirm`
  (24 места) — в кнопке подтверждения стоит глагол действия, Esc/фон = отмена, фокус в ловушке.
  `withBusy(btn, fn)` — единое busy-состояние команд к плате.

  pill «связь с платой потеряна», значения в muted, команды Testing блокируются. Раньше сокет
  молча переподключался и замерший снапшот выглядел живым.
- **Logger**: сегмент «показ / выбор» (`params--view`, режим в `localStorage`). «Показ» —
  только выбранные каналы плитками, значение 32 px (26 px в ландшафте), спарклайн во всю ширину.
- **Оформление**: `data-theme` на `<html>` + выбор Авто/Светлое/Тёмное в Cfg → Система
  (`localStorage`, преференция устройства). Тёмная палитра продублирована для media-запроса и для
  `:root[data-theme="dark"]`.
- **Безопасность разметки**: `esc()` на имена файлов в списках логов/прошивок и на ECU-баннер —
  загруженный `.bin` с кавычкой в имени раньше ломал строку и позволял вставить разметку.
- **Ландшафт/вырезы**: горизонтальные `env(safe-area-inset-left/right)` у topbar/tabs/main/баннера,
  `@media (max-height: 500px)` — компактные шапка и вкладки (−40 px вертикали), плитки от 130 px;
  `min(340px, 55dvh)` у графика, `max-height: calc(100dvh - 32px)` у модалки.
  `manifest.json` + иконки: установка на экран «Домой», `orientation: any`.
- **Тач-цели** маркеров/актуаторов/DTC — 44 px. Приглушение состояний — цветом, не `opacity`.
- Побочный фикс: `.mini[hidden]` проигрывал `display:inline-flex`, из-за чего кнопки Cancel
  (прошивка) и Stop (актуаторы) были видны всегда.

## Копирование DTC в буфер (2026-08-28, задеплоено на плату)
- Кнопка **Copy** (`#dtcCopyBtn`) в карточке Fault codes рядом с Read/Clear. Скрыта, пока в
  `#dtcResult` пусто; появляется на любой результат — включая «нет ошибок», «стёрто» и ошибку
  связи (её как раз и хочется вставить в переписку).
- Копируется **не** соскоб HTML, а plain-text двойник, который `renderDtc()` собирает
  параллельно с разметкой: заголовок + локальное время, строка счётчика, по строке на код
  (`P0107 · описание · stored · тип 2 · ⚠ · 0x2a`) и сырой кадр. Статус-байт в вёрстке живёт
  только в `title=`, из DOM его не вытащить.
- **Важно про буфер на телефоне:** плата отдаёт UI по `http://` со своей точки доступа, а вне
  secure context `navigator.clipboard` на телефоне просто отсутствует. Поэтому
  `copyToClipboard()` сначала пробует Clipboard API (и только при `window.isSecureContext`), а
  затем всегда падает на скрытый `<textarea>` + `document.execCommand("copy")`; iOS игнорирует
  `.select()` у readonly-поля, так что выделение делается через `Range` + `contentEditable`.
  Неудачное копирование говорит об этом тостом, а не молчит.
- Кнопка намеренно не входит в `updateTestingButtons()`: результат остаётся нужным и после
  обрыва связи с ECU.
- Тест: `tests/test_ui_dtc_copy.py` → `tests/ui_dtc_copy.js` (app.js целиком грузится в Node vm
  на заглушке DOM, кликается реальный обработчик; проверены обе ветки копирования).

## Опознание прошивок по содержимому образа (2026-08-28, на плате проверено чтение, запись — нет)

**Код калибровки лежит внутри образа.** Смещения взяты из TunerPro XDF
(`5AM_Morini_23ECCLGPS_merged.xdf` (вне репозитория)) и сверены со всеми пятью образами в `/root/firmware`:

| поле | смещение | длина | пример |
|---|---|---|---|
| маркер | `0x47FA0` | 4 | `55 AA 33 CC`, во всём образе 3 вхождения |
| Map Name 1 | `0x47FA4` | 12, пробелы | `23EC` |
| Map Name 2 | `0x48006` | 16, пробелы | `CLGPSMB` / `CLGPSMC` / `CLGPSMD` |
| hardware | `0x48016` | 16, NUL | `5AM X0000` |

`Map Name 1 + Map Name 2` = `Drawing`, те же 11 символов, что `config/ecu_id.json` режет из живого
`1A 80`. XDF также называет Software Date (`0x47F82`) и Software Version (`0x47F96`), но на всех
наших образах там филлер, и при чтении они подбирают байты маркера — в layout намеренно не заведены.

**Сверка (`dd` по образам на плате):**

| файл | внутри | sidecar |
|---|---|---|
| `23ECCLGPSMB.bin` | MB | MB ✓ |
| `23ECCLGPSMC.bin` | MC | — |
| `23ECCLGPSMD.bin` | MD | MD ✓ |
| `my_original_fw.bin` | MC | MC ✓ |
| `granpasso_v4_draft.bin` | **MC** | **MD** ✗ |

Последняя строка — реальная ошибка: draft v4 собран на базе **MC**, а подписан MD. Приложить к нему
XDF от MD — редактировать таблицы по чужим адресам. Ради поимки ровно этого и делалась фича.

**Пространства имён не путать.** Живой `Drawing` и код образа — разные вещи. У Morini совпадают, у
других марок нет (реальные дампы с форумов):

| марка | Drawing | Hardware | Omologation | Software | Tester |
|---|---|---|---|---|---|
| Moto Morini Granpasso | `23ECCLGPSMD` | `IAW5AMHW610` | — | — | — |
| Ducati 1098 | `96520610B` | `IAW5AMHW610` | `5AMR4` | `3215SWA5` | `DUC` |
| Moto Guzzi | `28640921A` | `IAW5AMHW103` | `5AMA5` | `1210EA09` | `TLC` |

Поэтому гард (`app/web/fw_guard.py`) сравнивает **бренд+модель, разрешённые через каталог**, а не
строки: наивное сравнение заблокировало бы любую законную запись на Ducati и Guzzi.

**Что где:**
- `app/kline/fw_ident.py` — читает только окно ~136 байт (`/api/firmware` опрашивается раз в 1.5 с).
- `config/fw_layout.json` — смещения; другое семейство ECU = ещё один layout, без Python.
- `config/fw_catalog.json` — код → мотоцикл. **Слоями**, не заменой: `/etc/onboard-logger/fw_catalog.json`
  мержится поверх, иначе первая правка из UI стёрла бы зашитые записи. Записи из UI помечены
  `user: true`, только их и можно удалять.
- `app/web/fw_guard.py` — таблица решений; жёсткий блок только `model_mismatch`.
  Гард вызывается в `FirmwareManager.start_write()`, мимо HTTP-слоя не обойти.
- Тумблер `system.fw_guard_override` (Cfg → Sys, по умолчанию выкл) понижает блок до предупреждения;
  пока включён — красный баннер в карточке Write, а в лог операции уходит `[!] guard overridden`.
- Паспорт `<name>.bin.txt` дополнен строками `Brand` / `Model` / `Image` / `Catalog`; `parse_desc()`
  читает его обратно. Формат GuzziDiag сохранён: первая строка `Drawing:`, конец CRLF.
- Имя дампа предлагается из живого `Drawing` (`<Drawing>-<YYYYMMDD>.bin`) — поле редактируемое,
  подстановка прекращается, как только в него что-то ввели. После чтения, если байты не сошлись с
  именем, предлагается переименование (`/api/firmware/rename` двигает `.bin` и `.bin.txt` вместе).

**Каталог (334 записи).** 13 курируемых + 321 справочная из списков прошивок TuneECU
(Morini/Guzzi/Ducati/Aprilia/Benelli/Gilera). Справочные помечены `"guard": false`: имя мотоцикла в
UI показывают, но сторону для гарда не разрешают — в исходнике одна и та же машина зовётся и `1098`,
и `1098S`, и `Superbike 1098 (USA)`, и такое решение блокировало бы законную запись. Курируемые
записи побеждают импорт (`exact` бьёт префикс, поэтому коды Granpasso при импорте пропущены — иначе
пропало бы предупреждение о ревизии между MC и MD). Triumph/BMW/CCM/Husqvarna не брали: другие
семейства ECU (Sagem/Keihin/BMS-K), к IAW отношения не имеют, а Triumph — это ещё 600+ строк.
Самодельные тюны (`EbisUltimativeRace*`, `*_CATFISH_*`) отброшены: это имена файлов, а не коды
калибровок. У 54 записей Aprilia из описания вытащен ECU (`7SMHW100/110/310`).

Карточка каталога свёрнута (`<details id="fwCatalogBox">`) и внутри — дерево
производитель → модель → коды, тоже на `<details>`. Поиск (`#fwCatSearch`) фильтрует по **коду
прошивки**: подстрока, а полный код находит покрывающее его семейство (`23ECCLGPSMD` → `23ECCLGPSM`),
плюс совпадения по ревизиям. Пока в поиске что-то введено, найденные группы раскрыты; вручную
раскрытые запоминаются в `fwCatOpen` и переживают перерисовку. Счётчик у заголовка показывает
`найдено / всего`.

Эндпоинты: `GET /api/firmware/check`, `POST /api/firmware/rename`,
`GET/POST /api/firmware/catalog`, `DELETE /api/firmware/catalog/{code}`.

## Верифицированная карта 5AM (GuzziDiag v0.42 reverse `sub_41C367`, сверено с захватом 2026-08-18)
Референсы: `guzzidiag_v042_reverse.md` (вне репозитория) (сводка) + `guzzidiag_V0.42.exe.txt` (декомпайл). Ответ `61 <rli> <value>`, big-endian, offset 2.
- 0x30 RPM=raw · 0x32 Coolant=raw−40°C · 0x33 Air=raw−40°C · 0x34 Throttle=raw/10° · 0x35 Advance=raw°(? ~200, сверить) · 0x37 Injection=raw/20 ms · 0x3B CO/duty · 0x3C Battery=raw/10 V · 0x45 Lambda L=raw mV · 0x46 Lambda R=raw mV · 0x47 Fuel trim L=raw/100% (signed) · 0x48 Fuel trim R=raw/100% (signed).
- Проверено на моте: rpm idle~1500, throttle~1.8°, injection 4–29мс, battery 11.9–14.1В, lambda осциллируют. **2 лямбды = 0x45/0x46**.
- 0x3A = целевые обороты ХХ (1571 холодн → 1401 прогр), 0x39 = выход регулятора ХХ (~1281 на ХХ) — расшифрованы 2026-08-21, перенесены в именованные (default=true).
- Гипотезы в скобках у имени: 0x3E конфиг/ID (const 52), 0x49 статус-флаг (0/2, closed-loop?), 0x4B счётчик/статус (0–7), 0x54/0x55 сырые АЦП (?), 0x57 статус (const 4), 0x58 статус/передача? (0–7).
- Остальные rli (0x31,0x36,0x38,0x3D–0x44,0x49–0x7F) — читаются, но не именованы (raw). Точные имена — в ВНЕШНЕМ GuzziDiag.ini (`Value_1..45`), в бинаре нет. Дожать при желании из захвата.

## Инициализация тест-режима (разобрано 2026-08-22)
Реверс `sub_415D1B` (GuzziDiag, поток 5AM) и IAWDiag (стр. 37504+, 5 одинаковых потоков):
bring-up линка = `fast-init` → `81` → **`83 03 00 FF 00 FF 00`** (AccessTimingParameter,
subfn 03: P2min=00 P2max=FF P3min=00 P3max=FF P4min=00) → **`10 81`** StartDiagnosticSession
(сессия **0x81**, не 0x85) → цикл + `3E` каждые 3000 мс → teardown `20` + `82`.
Ответы на `83` и `10 81` оба тула игнорируют.
- **Отдельной команды входа в тест/адаптацию у 5AM нет** — `30 lid 07/00`, `31 21`, `30 7E 04`
  это обычные сервисы внутри той же сессии (грепнуты все сайты `10` в обоих бинарях).
- «Режим» в GuzziDiag — чисто UI: `sub_42ADD7(1,N)` дизейблит остальные кнопки тестов,
  `(0,-1)` возвращает их и снимает чекбоксы; полинг параметров не останавливается.
- Актюатор 5AM держится, пока нажат чекбокс (таймер авто-off есть только у ECU-индексов <5).
- Карта кнопок 5AM (`sub_42D2DB` case 5): pump=5, coil R=3, inj R=9, tacho=6
  (тела coil L / inj L отсутствуют в дампе; у соседних веток это `30 02` / `30 08`, совпадает
  с JPDiag `[Tests]`). Кнопка «Leerlaufregelung» (`dword_45D7F8 = sub_427BCF`) — тело
  отсутствует, команда не восстановлена (кандидат `30 04` stepper).
- TPS reset у 5AM — одиночный `31 21` без опроса завершения (опрос 500мс×20 только у 7SM).

**Реализовано в коде** (2026-08-22): `KWP2000Session.enter_test_mode()` (83+10 81, идемпотентно,
терпит NRC/таймаут), `end_link()` (20+82 при штатном разрыве), `actuator_set(lid, on)`.

## Диагноз «Ошибка: Load failed» при смене языка (2026-08-22)
`POST /api/config` за сутки в журнале — **0 штук**: запрос не доходил до сервера, а язык
переключался локально (`applyLocale` работает на клиенте). Причина окна недоступности:
`lifespan` синхронно звал `apply_network(prev=None)`, а без Wi-Fi донгла
`systemctl restart hostapd` висит **31 с** (в юните `ExecStartPre` ждёт `wlan0` 30 с) →
порт 80 не открывался ~20–31 с после каждого рестарта сервиса.
Исправлено: `ConfigManager.iface_present()` (проверка `/sys/class/net/<iface>`) — без
адаптера все шаги AP пропускаются с сообщением, в отчёте появляется `iface_missing`;
стартовый `apply_network` вынесен в фоновую задачу после подъёма сервера.
**Проверено на плате: окно старта 21 с → 3.3 с, `POST /api/config` отвечает за 0.02 с.**
Плюс автосейв: все не-сетевые поля Config сохраняются при изменении (зелёный баннер
«Настройки сохранены»), сетевые (`wifi.*`, `network.*`, `dhcp.*`, `hostname`) помечаются
жёлтой точкой и уходят только по кнопке Save. Сетевой сбой fetch теперь показывается как
«Плата не ответила — настройки НЕ сохранены», а не сырым `Load failed`.
Заодно починен `tests/test_logging.py` (жил на старых ключах `tps` до верифицированной карты).

## Wi-Fi: режимы AP ↔ клиент (2026-08-23)
`wifi.mode` = `ap` | `client`, режимы взаимоисключающие, всё в одном блоке Config → «Сеть Wi-Fi».
- **AP** (как раньше): hostapd + статический IP + dnsmasq. Новое поле `network.gateway` —
  пустое по умолчанию: dnsmasq тогда шлёт голый `dhcp-option=3` («шлюза нет»), клиенты не получают
  маршрут по умолчанию; если адрес задан — уходит `dhcp-option=3,<gw>`.
- **Client**: `wifi.client.{ssid,password,ipv4,ip,prefix,gateway,dns}`. Шаблон
  `app/templates/wpa_supplicant.conf.j2` → `/etc/wpa_supplicant/wpa_supplicant-wlan0.conf` (0600),
  `systemctl restart wpa_supplicant@wlan0`, адрес через `dhcpcd -b wlan0` либо вручную
  (`ip addr add` + `ip route replace default` + `resolvectl dns`). hostapd/dnsmasq глушатся,
  hostapd ещё и `disable`, чтобы не забрал радио после перезагрузки. DHCP-сервер не поднимается.
- **Страховка**: `wait_client_up()` ждёт ассоциацию + адрес 45 с (`cm.client_timeout`); не вышло —
  `_apply_client` сам поднимает AP обратно (`fallback_to_ap`), а `_after_network` в `main.py`
  пишет `wifi.mode="ap"` в config.json, чтобы и после перезагрузки плата была доступна.
- **Важно**: клиентская ветка отрабатывает только при изменении блока `wifi` — смена языка/K-Line
  живой линк не рвёт (тест `test_client_untouched_when_only_other_settings_change`).
- Эндпоинты: `POST /api/wifi/networks` (скан списка сетей; в AP-режиме гасит hostapd на время
  скана и поднимает обратно), `GET /api/wifi/status`. В снапшоте — `wifi_mode` и `wifi_link`
  (ssid/ip/signal), UI показывает строкой в блоке.
- Тесты: `tests/test_config_net.py` (11 шт, без системных вызовов — `_run` подменён рекордером).
- Проверено на плате **без донгла**: переключение в client отвечает за 0.02 с, `iface_missing`,
  радио не трогается, eth0/NetworkManager целы. Сквозная проверка ассоциации — после подключения
  USB-адаптера (см. локальный план-файл вне репозитория).

## Часы: RTC не поехал, время берём у браузера (2026-08-24)
DS1307 на i2c-0 **не отвечает** (0x68 NACK всеми методами), на шине живёт только его сосед —
пустая EEPROM 0x51 (все регистры 0xFF при любом виде чтения). Причина: DS1307 требует 4.5–5.5 В,
при 3.3 В уходит в батарейный режим и глушит I²C. Варианты: DS3231-модуль (3.3 В, TCXO), замена
чипа на DS1338 или питание 5 В с переносом подтяжек на 3.3 В. Встроенный `rk808-rtc` — без батарейки.
Шины: i2c-0 (`ff150000`, GPIO2_D0/D1) — разъём; i2c-1 — PMIC RK805 @0x18, не трогать.
На плату поставлен `i2c-tools`.

**Решение**: `system.auto_time_sync` (дефолт true) — первый веб-клиент после включения ставит дату,
время и таймзону. Маркер `/run/onboard-logger/time-synced` (tmpfs: чистится при перезагрузке,
переживает рестарт сервиса) → одна попытка на включение. Порог 2 с: при меньшем расхождении часы не
дёргаем, но попытку засчитываем. Неудача (мусорный epoch, нет timedatectl) маркер **не** ставит —
следующий клиент попробует. Эндпоинты `POST /api/system/time/auto`, `GET /api/system/time`
(+`auto_enabled`/`auto_done`); клиент шлёт запрос из `init()` в app.js, гонку вкладок решает маркер
на сервере (проверено вживую: два POST в одну секунду, синхронизация одна).
Чекбокс — Config → System, не сетевое поле, сохраняется автосейвом. Тесты: `tests/test_system_time.py`.

## Разрыв лога на несколько файлов = отвал USB-хаба (разобрано 2026-08-31)

**Симптом:** 26.08 было две поездки, а `kline-dec-*.csv` за вечер оказалось три штуки
(19:00:10→19:04:01, 19:04:04→19:05:40, 19:05:43→19:12:14), заголовки одинаковые, дырки 3.2 и 3.3 с.

**Причина (из `/var/log/kern.log.1`, rsyslog):**
```
19:04:01.798 usb usb2-port1: disabled by hub (EMI?), re-enabling...
19:04:01.798 usb 2-1: USB disconnect      <- сам хаб (ALCOR 058f:9254)
19:04:01.798 usb 2-1.1: USB disconnect    <- FTDI FT232R = /dev/kline
19:04:01.810 usb 2-1.3: USB disconnect    <- Ralink RT5370 = wlan0
19:04:02.278 usb 2-1: new full-speed USB device number 5   (вернулся через ~0.5 с)
```
То есть падает **весь хаб**, и одним событием умирают K-Line и Wi-Fi (в syslog рядом
`dnsmasq: error binding DHCP socket to device wlan0`). pyserial отдаёт мгновенный `OSError`,
`run()` в `finally` зовёт `_close_all_logs()` → файл закрыт; через `reconnect_delay`=2 с линк
поднимается и открывается **новый** файл. Одна поездка = один файл нигде не заложено.

Путь «ЭБУ замолчал» арифметикой исключён: он требует 8 таймаутов ×150 мс + провал TesterPresent
(≥1.35 с), а на обнаружение в бюджете 3.2 с остаётся ~0.3 с. Плюс перед обрывом ноль строк
с пустыми ячейками — шина отвечала на 100 % до последней строки.

Частота по сохранившимся kern.log: 18 событий `disabled by hub` (18.08 ×2, 20.08 ×13, 25.08 ×1,
26.08 ×2). Хроника; причину EMI/просадка лог не назовёт — на RK3328 нет измерения тока USB.

**Побочные факты этого разбора:**
- Утренний файл 26.08 не разрывался, но содержит скачок часов +1:38 на 10:01:36 (нет RTC,
  время выправляется от браузера) — метки до синхронизации врут, данные непрерывны.
- `journalctl` за 26.08 пуст (журнал того бута не долетел на SD при срыве питания зажиганием),
  а rsyslog `/var/log/{syslog,kern.log}` — сохранился. Поэтому диагностика пишется и туда.
- Признак в списке файлов: `rpm=0` в последней строке = нормальный конец (зажигание выкл),
  `rpm>0` = обрыв. Разрыв 0.6 с со сменой заголовка (25.08 19:01:34) — это не обрыв,
  а перекат файла из-за смены набора параметров.

## Verbose-лог операций с прошивкой (2026-09-01)

На каждое чтение/запись пишется `<log_dir>/fw-<op>-<ts>.log`. `-v` у `5am_util` теперь передаётся
всегда (галочка в UI решает лишь, показывать ли в списке каждую строку или только вехи и всё
похожее на сбой). В файле: команда, размер+sha256 образа, идентичность ECU, факты USB из sysfs
(`vid/pid/serial`, `usbpath=2-1.1`, драйвер, `latency_timer`) до и после операции, результат
`request_pause` воркера, все строки утилиты, строки ядра за время операции (свой `KmsgReader` —
работает даже если diag-лог выключен), посекундная проверка `/dev/kline` (исчезновение узла прямо
посреди прошивки пишется и в файл, и в UI) и, при неуспехе, хвост `dmesg`. Смотреть:
Config → System, блок «Логи операций с прошивкой»: список файлов, открыть
(`/api/firmware/log.txt?file=<имя>`) или скачать. Во вкладке логов их нет специально —
`_is_ride_log()` в `main.py` единственное место, решающее, что туда попадает. Потолок файла 16 МБ.

**Найдено этой же проверкой:** `5am_util` без кабеля печатает `ERROR: ioctl: Bad file descriptor`
(main.c:494) и **выходит с кодом 0** — раньше неудачное чтение показывалось как «готово» и даже
сохраняло `.txt`-описание. Теперь вердикт (`_verdict()`) ставится по трём признакам: код возврата,
строка ошибки в выводе утилиты (ANSI-цвета срезаются) и результат на диске — файл создан и его
размер равен `firmware_size`. В UI показывается сама причина, а не «код возврата 0».
