# Что дали ПК-программы диагностики

Каталог всего, что извлечено из декомпилированных Windows-тулов: что уже используется в
логгере, а что сознательно не трогаем. Дополнение к `PROTOCOL.ru.md` (там сам протокол).

Исходники лежат на машине автора, в репозитории их нет:

| артефакт | что это |
|----------|---------|
| `guzzidiag_V0.42.exe.txt` | декомпиляж Hex-Rays, 59 тыс. строк, PureBasic. Самый полный источник. |
| `IAWDiag_V0.52.exe.txt` | декомпиляж того же автора/архитектуры, **шесть** семейств ECU. |
| `GuzziDiag_V0.61.exe`, `GuzziDiag_V0.60.app` | более новые сборки, только бинарники |
| `JPDiag28c.exe` + `JPDiag28c.ini` + `lang/*.ini` + `*Dtc.dll` | сторонний VB6-тул; декомпиляж мусорный, но ресурсы текстовые и полезные |

## 1. Имена переменных — нет

Оба бинаря без символов. Всё, что названо в наших заметках (`sub_415D1B`, `unk_45D938`, …) —
это адрес, а не имя. Восстанавливается **роль** нескольких глобалов, потому что они пишутся
прямо перед каждым вызовом транспорта:

| глобал (GuzziDiag / IAWDiag) | роль |
|------------------------------|------|
| `unk_45D938` / `unk_495598` | байт сервиса (0x21, 0x30, 0x31, …) |
| `unk_45D939` / `unk_495599` | LocalID / подфункция |
| `unk_45D93A` / `unk_49559A` | второй параметр |
| `dword_45D934` / `dword_495594` | формат кадра: 2 = адресный, 0 = короткий |
| `dword_45D92C` / `dword_49558C` | длина payload для comm-потока |
| `byte_45D949` / `byte_4955A8` | байты ответа |

Этого хватает, чтобы перечислить вообще все запросы, которые тул умеет слать — так и собран
остальной документ.

## 2. Имена параметров — **их нет ни в одном бинаре** (проверено дважды)

- Тексты UI лежат под ключами (`View_42`, `Value_1`…`Value_69`, `Fault_3`…), а сами строки
  грузятся из внешнего `GuzziDiag.ini` / `IAWDiag.ini`, который создаётся рядом с exe.
- Скан обоих бинарей по UTF‑16 даёт только *ключи*, никогда — подписи.
- Встроенный дефолтный INI из GuzziDiag V0.42 (`byte_452348`, 4056 байт, восстанавливается
  из декомпиляжа целиком) содержит `[Settings] [Modells] [Deutsch]` — меню, кнопки и таблицу
  моделей, но **никаких `Value_N`**.
- Структурно там и нечего называть: диспетчер параметров каждого семейства — это просто по
  одному геттеру `21 <rli>` на каждый rli подряд (см. §4), семантики каналов тул не знает.

Вывод: имена каналов 5AM берутся только из захватов (как уже сделано в `config/params.json`
для 12+ каналов) либо из чужого готового `.ini`.

## 3. Инициализация режимов — да, полностью

См. `PROTOCOL.ru.md` §4.1. Сессия одна, поднимается при коннекте обоими тулами:
`81` → `83 03 00 FF 00 FF 00` → `10 81`, держится `3E`, закрывается `20` + `82`.
Отдельного сервиса «войти в режим тестирования» нет: тесты актюаторов и сбросы адаптаций —
обычные сервисы внутри этой сессии. **Реализовано** (поднимается лениво при первой команде
с вкладки Testing, чтобы не трогать путь логгера).

## 4. Матрица команд по семействам (IAWDiag V0.52)

В IAWDiag шесть семейств ECU, у каждого свой comm-поток и своя транспортная функция.
Группировка всех не-опросных сервисов по транспорту даёт матрицу возможностей:

| транспорт | блок rli | встреченные сервисы |
|-----------|----------|---------------------|
| `sub_41B3A7` | 0x30–0x75 + 0xA6 | `18 00`, `1A 00`, `30 02/03/04/05/08/09 07`, `30 15 05`, `30 20 07`, `30 7E 04`, `31 21` |
| `sub_4158D0` | 0x30–0x7C + 0xA6 | `14 FF 00`, `14 FF 24`, `18 00`, `30 02/03/04/06/07/08/0C/0F/11/20/79 07`, `30 7E 04`, `31 21`, `31 24`, `33 21`, `33 24` |
| `sub_4043F7` | 0x30–0x75 + 0xA6 | `14 FF 00`, `18 00`, `30 02/03/05/08/09/0A/0B/20 07`, `30 7E 04` |
| `sub_4115A6` | 0x00–0xA1 | `14 FF 00`, `18 00`, `30 08/09/23 07`, `30 7E 04`, `31 22/25/28 03/2E`, `33` |
| `sub_4545C6` | 0x00–0x8F + 0xB0 | `18 00`, `30 02/03/05/08/09/23 07`, `30 7E 04`, `31 22`, `31 23` |
| `sub_42C7DD` | 0x30–0x7E + 0xA6 | `18 00`, `30 0C/79 07`, `33 24` |

`sub_41B3A7` — то семейство, чей набор актюаторов совпадает с Guzzi 5AM (катушки 2/3,
форсунки 8/9, насос 5, шаговик 4), поэтому именно его «лишние» команды нам интересны:
**`30 20 07`** и **`30 15 05 <value>`** (второе — CO-триммер, §6).

`31 24` + `33 24 <n>` у `sub_4158D0` читает многозаписный блок и пишет файл с именем
`MIU1 StoredData` — это дамп сохранённых данных MIU, не фича 5AM.

## 5. Коды ошибок — чтение, стирание и статус-байт

`18 00 FF 00` / `14 FF 00` были реализованы раньше. Новое из этого захода — **как оба тула
раскладывают статус-байт** (экран DTC у GuzziDiag, IAWDiag @26617/26655):

```
status & 0x0F   тип неисправности: 1 / 2 / 4 / 8  -> подписи Fault_3..Fault_6 (внешний ini)
status & 0x20   1 -> список сохранённых ("Gespeicherte Fehler")
                0 -> список текущих/новых ("Neue Fehler")
status & 0x40   индикатор предупреждения (лампа)
```

GuzziDiag грубее: `status & 0x60 != 0` → сохранённая. IAWDiag считает `(status & 0x60) >> 5`
и относит 1 и 3 к сохранённым, то есть решает бит 0x20. **Реализовано** — на вкладке Testing
теперь видно *сохранённая / текущая*, номер типа и ⚠, а сырой байт и его биты — в тултипе.
Словесные подписи типов 1/2/4/8 лежат во внешнем файле локализации и не восстановимы,
поэтому показывается номер.

`*Dtc.dll` из JPDiag — обычные таблицы кодов SAE J2012 (2084 кода × 4 языка), уже
импортированы в `config/dtc/`.

## 6. CO-триммер — восстановлен, но сознательно **не реализован**

Экран «CO Einstellung» у GuzziDiag для 5AM (`sub_41EFFC`, привязан как `dword_45D8E4`):

```
30 15 07 <value>     проба / применить на сессию
30 15 05 <value>     записать  (экран +/- выставляет бит 0x100 в аргументе, чтобы выбрать 05)
value: знаковый, ограничен -128..127
```

Форма «Trimmer» у JPDiag — та же фича с явными условиями: двигатель прогрет (ОЖ ≥ 40 °C),
прочитать текущее значение, *test*, затем *confirm*; в подписи сказано, что заводское
значение для Ducati 749S лежит между 22 и 29.

Это запись в ECU, семантика commit не подтверждена сниффом, а тюнингом владелец занимается
через прошивку — поэтому фича задокументирована здесь и в `config/profiles.json`, и ничего
не отправляется.

## 7. Пресеты мотоциклов — восстановлены полностью

Секция `[Modells]` встроенного INI сопоставляет **65 моделей Moto Guzzi** семейству ECU и
варианту транспорта, например `Griso 1200 8V = 5AM,PF2C`, `Breva 750 = 15RC,PF1C`,
`V7 Stone = MIUG3`. Перенесено дословно в `config/profiles.json` вместе с матрицей команд по
ECU и показывается только для чтения на вкладке Testing. Теги протокола (PF09/PF10/PF1C/
PF2C/PF3C) выбирают процедуру подъёма K-line, а не идентификаторы сервисов.

Команды адаптаций различаются по семействам — ровно поэтому пресеты и нужны:

| ECU | сброс TPS | самоадаптация | примечание |
|-----|-----------|---------------|------------|
| 5AM | `31 21` | `30 7E 04` | проверено на этом моте |
| 15RC | сырой байт `0x89` | сырой байт `0x8A` | проприетарный обмен с эхом, не KWP |
| MIUG3 | `31 21` | — | другой транспорт |
| 7SM | `31 23` + `33 23`, опрос 20 × 500 мс | — | полное обучение, а не сброс |

## 8. Мелочи, вошедшие в код

- **`33 <lid>` RequestRoutineResults** — так IAWDiag подтверждает завершение рутины у тех
  семейств, что её поддерживают. У 5AM ни один тул её не шлёт, поэтому мы пробуем
  best-effort после `31 21` и показываем что вернулось (обычно отрицательный ответ).
- **`1A 00`** — 5AM-семейство в IAWDiag читает идентификацию опцией 0x00, мы спрашивали
  только 0x80. Теперь читаются обе, все ответившие блоки сохраняются.
- **`30 20 07`** — добавлен в `config/actuators.json` с пометкой «не проверено» (`*`).
  Вероятный регулятор ХХ за кнопкой *Leerlaufregelung* у GuzziDiag, тело обработчика в
  дампе отсутствует.
- **Формат кадра**: GuzziDiag читает параметры 5AM **коротким** заголовком
  (`dword_45D934 = 0`, `[len][data][cs]`), мы — адресным. ECU принимает оба, а наш скан всё
  равно пишет обе рамки.
- **«Frage alles ab»** (`View_12`, пишет `TestResultate.txt`) — это собственный свип rli у
  GuzziDiag; наш Full parameter scan уже покрывает 0x00–0xFF в обеих рамках и пишет CSV по
  каждому проходу.

## 9. Сознательно вне объёма

- **Иммобилайзер / «Unlock ECU»** (Form4 у JPDiag: тест «девственности», 5-значный код с
  карточки, список состояний ECU 0–8). Крипта из VB6-декомпиляжа не восстанавливается —
  видна только примитива `byte ^0xE9 ^0x3E ^0x30`. Нужен чистый декомпиляж или снифф
  seed/key.
- **`31 22 / 24 / 25 / 28 03 / 2E`** — рутины других семейств IAWDiag. Слать неизвестные
  идентификаторы рутин в 5AM — неизвестные последствия; задокументировано, не отправляется.
- **`14 FF 24`** — вариант очистки DTC для другой группы, встречается только у семейства MIU.
- **Service reset / сброс ремней / «Gasgriff anlernen»** — есть как подписи кнопок
  (`View_58`, `View_59`) и в JPDiag, но команда для 5AM не восстанавливается.
