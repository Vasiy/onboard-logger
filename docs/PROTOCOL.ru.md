# Диагностический протокол IAW 5AM — референс

Восстановлено из декомпиляции **IAWDiag V0.52**, **GuzziDiag V0.42 / V0.61** и **JPDiag 28c**
(плюс открытый `JPDiag28c.ini`) и сверено с живым захватом на мотоцикле Moto Guzzi с ECU
**Magneti Marelli IAW 5AM (HW610)**.

English version: [PROTOCOL.md](PROTOCOL.md).

---

## 1. Физический уровень

- **KWP2000 / ISO 14230** по однопроводной **K-Line**, **10400 бод, 8N1**, без управления потоком.
- Полудуплекс: всё, что тестер передаёт, эхом возвращается по RX до ответа ECU — эхо надо прочитать
  и отбросить.
- В кабеле трансивер класса L9637D; TXD FTDI напрямую K-Line не тянет.

## 2. Формат кадра

Адресный кадр (в обе стороны):

```
[FMT] [TGT] [SRC] [DATA ...] [CS]
FMT = 0x80 | len      len = число байт DATA (1..63)
TGT = 0x10 (ECU)      SRC = 0xF1 (тестер)         запрос:  [.. 10 F1 ..]
CS  = сумма всех предыдущих байт & 0xFF           ответ:   [.. F1 10 ..]
```

Короткий кадр (без адреса), старшие биты `FMT` = `00`:

```
[len] [DATA ...] [CS]
```

IAW 5AM отвечает на оба framing при чтении; инструмент по умолчанию шлёт адресные кадры.

## 3. Инициализация

Два способа, выбор в Config → K-Line bus → Init.

**Fast init** (по умолчанию): K-Line вниз на **25 мс** (serial BREAK), отпустить на **25 мс**,
затем StartCommunication.

**Slow init (5-baud)**: bit-bang адреса **0x33** на 5 бод (200 мс/бит — покой высокий, старт-бит
низкий, 8 бит данных LSB-first, стоп высокий) через BREAK. ECU отвечает на 10400 бод: `0x55` (sync),
`KW1`, `KW2`; тестер шлёт **инвертированный KW2**, ECU — **инвертированный адрес** (`~0x33 = 0xCC`).
StartCommunication после не нужен — slow init сам устанавливает сессию.

## 4. Сессия (live-данные)

```
(init)
-> 81                 StartCommunication          (только fast init)
<- C1 EA 8F ...        positive + keybytes
   ... цикл опроса ...
-> 3E                 TesterPresent (keep-alive)  при простое > 3 с
-> 82                 StopCommunication           при выходе
<- C2 ...
```

Live-путь **не** шлёт `10 85` StartDiagnosticSession и `1A` ReadEcuId для опроса — IAW 5AM
отклоняет `10 85` с NRC 0x22 (conditionsNotCorrect). (`1A 80` ReadEcuId используется отдельно
один раз для блока идентификации — см. §8.) Восстановлено из IAWDiag `sub_423242`.

### 4.1 Диагностическая сессия (нужна для §6 и §7)

Оба ПК-тула сразу после `81` поднимают сессию — GuzziDiag `sub_415D1B` (поток 5AM),
IAWDiag (пять одинаковых потоков, один на семейство ECU):

```
-> 83 03 00 FF 00 FF 00   AccessTimingParameter (subfn 03 = задать значения:
                          P2min=00 P2max=FF P3min=00 P3max=FF P4min=00)
-> 10 81                  StartDiagnosticSession, сессия 0x81 (НЕ 0x85!)
   ... цикл ...
-> 20                     StopDiagnosticSession   при выходе
-> 82                     StopCommunication
```

Ответы на `83` и `10 81` оба тула **не проверяют** — шлют и идут дальше.

**Отдельной команды «войти в режим тестирования» у 5AM нет**: `31 21`, `30 7E 04` и
`30 <lid> 07/00` — обычные сервисы внутри этой сессии (в обоих бинарях сервис `0x10`
встречается только в bring-up). «Режим» в GuzziDiag — чисто UI: пока идёт один тест,
остальные кнопки дизейблятся (`sub_42ADD7`), полинг параметров при этом не прерывается.

Логгер поднимает эту сессию **лениво — перед первой командой с вкладки Testing**
(`KWP2000Session.enter_test_mode`), потому что `21 <rli>` работает и в дефолтной сессии.

Negative response: `7F <SID> <NRC>` (0x10 generalReject, 0x11 serviceNotSupported,
0x12 subFunctionNotSupported, 0x22 conditionsNotCorrect, 0x31 requestOutOfRange, …).

## 5. Live-параметры — сервис 0x21 (ReadDataByLocalIdentifier)

Каждое измерение — **отдельный** запрос; блочного «read all» нет.

```
-> 21 <rli>
<- 61 <rli> <value...>        байты значения = DATA ответа с offset 2, big-endian, 1..3 байта
```

IAW 5AM отвечает на все `rli` в **0x30..0x7F** (79 живых идентификаторов на тестовом моте). Длина
значения своя у каждого rli, берётся из длины кадра. Имена и формулы — из **диспетчера GuzziDiag
V0.42 `sub_41C367`**, сверены с захватом (RPM ~1500 на ХХ, впрыск 4–29 мс, АКБ ~12–14 В, лямбды
осциллируют):

| rli  | канал           | формула   | ед.  | примечание |
|------|-----------------|-----------|------|------------|
| 0x30 | RPM             | raw       | об/мин | ХХ ~1500, раскрутка до ~4500 |
| 0x32 | Темп. воздуха   | raw − 40  | °C   | ~окружающая |
| 0x33 | Темп. ОЖ        | raw − 40  | °C   | растёт при прогреве |
| 0x34 | Дроссель        | raw / 10  | °    | ХХ ~1.8° |
| 0x35 | Опережение      | raw       | °    | ~200 raw — уточнить масштаб |
| 0x37 | Впрыск          | raw / 20  | мс   | 4–29 мс |
| 0x39 | Регулятор ХХ    | raw       | об/мин | выход регулятора ХХ; ~1281 на прогретом ХХ, отстаёт от факт. rpm в движении |
| 0x3A | Целевые ХХ      | raw       | об/мин | целевые обороты ХХ от темп.: 1571 холодный → 1401 прогретый (совпало с картой ECU) |
| 0x3B | CO / duty       | raw       | %    | 8-бит |
| 0x3C | АКБ             | raw / 10  | В    | 11.9–14.1 В |
| 0x45 | Lambda F (перед)| raw       | мВ   | осциллирует (closed loop) |
| 0x46 | Lambda R (зад)  | raw       | мВ   | 2-я лямбда |
| 0x47 | Fuel trim F     | raw / 100 | %    | signed 16-бит |
| 0x48 | Fuel trim R     | raw / 100 | %    | signed 16-бит |

Цилиндры — **F/R (передний/задний)** по компоновке V-twin Moto Guzzi / Ducati / Moto Morini.
Остальные `rli` (0x31, 0x36, 0x38, 0x3D–0x44, 0x49–0x7F) читаются, но не именованы; их метки — во внешнем
GuzziDiag.ini (`Value_1..45`), в бинаре их нет. По захвату от 2026-08-21 для части есть рабочая гипотеза,
она вынесена в имя параметра в скобках: 0x3E — конфиг/ID-байт (константа 52), 0x49 — статус-флаг (0/2,
closed-loop?), 0x4B — счётчик/статус (0–7), 0x54 / 0x55 — сырые АЦП-каналы (слабая корреляция +0.2 с rpm
и впрыском), 0x57 — статус (константа 4, редко 16), 0x58 — статус/передача? (0–7).

Схема `config/params.json`: `{key, name, rli, fmt(2/0), offset, length, endian, signed, scale,
bias, recip, digits, default}`. `recip != 0` → `value = recip / raw` (период). `default` = выбран
для decoded-лога при старте (именованные вкл, неопознанные выкл). Worker опрашивает **только
выбранные** — меньше галок = выше poll rate.

## 6. Сбросы адаптаций (верифицировано для IAW 5AM)

Из GuzziDiag V0.42 (`sub_422EC3`, `sub_40D4D1`) и V0.61 (`sub_410172`). Делать на заглушённом
двигателе (kill-switch), зажигание включено.

| функция              | запрос      | positive-ответ | сервис |
|----------------------|-------------|----------------|--------|
| **Reset TPS** (Drosselklappe zurücksetzen) | `31 21` | `71 21` | StartRoutineByLocalId |
| **Reset самоадаптации** (Selbstadaption)   | `30 7E 04` | `70 7E` | IOControlByLocalId |

> IAW 5AM PF1C и PF2C используют одни и те же команды; у PF3C кнопки TPS reset нет. Другие семейства
> отличаются (IAW15RC — проприетарный байт 0x89; IAW7SM — `31 23` + таймер; MIUG3 — `31 21`, другой
> транспорт). GuzziDiag V0.61 переструктурировала TPS reset на data-driven сервис `0x33`; команда на
> проводе для 5AM не изменилась (`31 21`), но 100% подтвердит только снифф K-Line.

## 7. Тесты актуаторов — сервис 0x30 (InputOutputControlByLocalIdentifier)

```
-> 30 <localid> 07        включить
-> 30 <localid> 00        выключить
<- 70 <localid> ...        positive
```

LocalID → актуатор из `JPDiag28c.ini [Tests]`, командный байт 07/00 из GuzziDiag V0.61.
У 2-цилиндровой Guzzi часть из них отсутствует — вернут NRC.

| id | актуатор | id | актуатор |
|----|----------|----|----------|
| 1  | Реле компрессора кондиционера | 10 | Форсунка цил. 3 |
| 2  | Катушка (передний цил.)        | 11 | Форсунка цил. 4 |
| 3  | Катушка (задний цил.)          | 12 | Реле вентилятора 1 |
| 4  | Шаговик ХХ                     | 13 | Реле вентилятора 2 |
| 5  | Реле бензонасоса               | 14 | Подогрев лямбды 1 |
| 6  | Тахометр                       | 15 | Подогрев лямбды 2 |
| 8  | Форсунка (передний цил.)       | 16 | Клапан адсорбера |
| 9  | Форсунка (задний цил.)         | 17 | Сигнальная лампа |
|    |                                | 18 | Лампа темп. ОЖ |

GuzziDiag держит выход включённым, пока нажат чекбокс (таймера в ECU нет; авто-off по таймеру
есть только у ECU-индексов < 5). Логгер вместо этого шлёт **кратковременный импульс**:
`07` отправляет команда, `00` — поллинг-цикл воркера по дедлайну. Длительность настраивается на
вкладке Testing (дефолт 5 с, кламп 0.5–30 с). Таймингом владеет плата, поэтому живые значения не
замирают на время теста, а выход гаснет даже если браузер закрыли или ушли из зоны Wi-Fi.

Кнопки 5AM в GuzziDiag (`sub_42D2DB` case 5) подтверждают часть карты: бензонасос=5,
катушка R=3, форсунка R=9, тахометр=6.

### 7.1 Результаты рутин — сервис 0x33

`33 <localid>` (RequestRoutineResultsByLocalIdentifier) — так IAWDiag подтверждает завершение
рутины у тех семейств, которые на неё отвечают (`31 21`, затем `33 21`). Для 5AM ни один тул
её не шлёт, поэтому логгер пробует её best-effort после сброса TPS и показывает ответ:
отрицательный ответ здесь — ожидаемое поведение, а не ошибка.

## 8. Коды ошибок и идентификация

Статус-байт так, как его раскладывают оба ПК-тула (экран DTC у GuzziDiag, IAWDiag
@26617/26655): `status & 0x0F` = тип неисправности (1/2/4/8, подписи лежат во внешнем файле
локализации), `status & 0x20` = сохранённая (0 = текущая/новая), `status & 0x40` = индикатор.
GuzziDiag грубее (`status & 0x60 != 0`); у IAWDiag `(status & 0x60) >> 5` относит 1 и 3 к
сохранённым, то есть решает бит 0x20.

- **Read DTC** — `18 00 FF 00` (ReadDTCByStatus) → `58 <count> [hi lo status]×count`. Каждый DTC —
  2-байтовый код SAE J2012 (`P/C/B/U` + цифры) + байт статуса. Описания — из JPDiag `*Dtc.dll`
  (открытые SAE-таблицы, en/es/fr/it).
- **Clear DTC** — `14 FF 00` (ClearDiagnosticInformation).
- **Идентификация ECU** — `1A 80` (ReadEcuIdentification) → поля по смещениям `config/ecu_id.json`:
  Drawing (0:11), Hardware (11:22), Omologation, Software, Tester, Date. Рендерится в
  GuzziDiag-совместимый `.txt` (Date = дата чтения), показывается в Firmware → Read и сохраняется
  рядом с дампом.

## 9. Чтение/запись прошивки

Программный путь ([`denandz/5am_util`](https://github.com/denandz/5am_util), собран под aarch64):
`10 85` StartDiagnosticSession → `27` SecurityAccess (seed/key) → смена baud → блочный transfer
(`34`/`36`) + checksum. Размер образа ровно **327680** байт (0x50000); запись другого размера
блокируется. Чтение ≈ 20 мин. ⚠ Запись рискует «окирпичить» ECU.

## 10. Статус-биты (JPDiag `JPDiag28c.ini`)

Декодеры в `config/status_maps.json` (привязать к status-rli после опознания):

- **motorstate** (биты): 01 Power-On/двиг. off, 02 Зажигание on/двиг. off, 04 Двигатель работает,
  08 Глохнет, 10 Power-Latch активен, 20 Power-Latch завершён.
- **motor** (биты cut-off, 16-бит): 0001 Crank … 0040 Steady running … 0400 In cut-off …
  2000 Выход из cut-off (разгон).
- **tps_state** (биты): 01 min, 02 полностью открыт, 04 середина.
- **immobilizer** (enum): 0 stored, 1 virgin, 2 no-start, 3 universal code, 5 backdoor code,
  6 erroneous key, 8 no code.
- **sidestand / clutch / gear / onoff** (enum'ы).
