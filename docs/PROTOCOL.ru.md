# Диагностический протокол IAW 5AM — референс

Ниже — то, что **Magneti Marelli IAW 5AM (HW610)** реально отвечает на шине: установлено
наблюдением и сверено с живым захватом на мотоцикле Moto Guzzi с этим ECU. Там, где значение
остаётся гипотезой, это сказано прямо.

English version: [PROTOCOL.md](PROTOCOL.md).

---

## 1. Физический уровень

- **KWP2000 / ISO 14230** по однопроводной **K-Line**, **10400 бод, 8N1**, без управления потоком.
- Полудуплекс: всё, что тестер передаёт, эхом возвращается по RX до ответа ECU — эхо надо прочитать
  и отбросить.
- В кабеле трансивер класса L9637D; TXD FTDI напрямую K-Line не тянет.

## 2. Формат кадра

Адресный кадр (в обе стороны):

```
[FMT] [TGT] [SRC] [DATA ...] [CS]
FMT = 0x80 | len      len = число байт DATA (1..63)
TGT = 0x10 (ECU)      SRC = 0xF1 (тестер)         запрос:  [.. 10 F1 ..]
CS  = сумма всех предыдущих байт & 0xFF           ответ:   [.. F1 10 ..]
```

Короткий кадр (без адреса), старшие биты `FMT` = `00`:

```
[len] [DATA ...] [CS]
```

IAW 5AM отвечает на оба framing при чтении; инструмент по умолчанию шлёт адресные кадры.

## 3. Инициализация

Два способа, выбор в Config → K-Line bus → Init.

**Fast init** (по умолчанию): K-Line вниз на **25 мс** (serial BREAK), отпустить на **25 мс**,
затем StartCommunication.

**Slow init (5-baud)**: bit-bang адреса **0x33** на 5 бод (200 мс/бит — покой высокий, старт-бит
низкий, 8 бит данных LSB-first, стоп высокий) через BREAK. ECU отвечает на 10400 бод: `0x55` (sync),
`KW1`, `KW2`; тестер шлёт **инвертированный KW2**, ECU — **инвертированный адрес** (`~0x33 = 0xCC`).
StartCommunication после не нужен — slow init сам устанавливает сессию.

## 4. Сессия (live-данные)

```
(init)
-> 81                 StartCommunication          (только fast init)
<- C1 EA 8F ...        positive + keybytes
   ... цикл опроса ...
-> 3E                 TesterPresent (keep-alive)  при простое > 3 с
-> 82                 StopCommunication           при выходе
<- C2 ...
```

Самому опросу не нужны ни StartDiagnosticSession, ни `1A` ReadEcuId. (`1A 80` ReadEcuId
используется отдельно один раз для блока идентификации — см. §8; `10 85 <код>` только
переводит сеанс на другую скорость — §4.2.)

### 4.1 Диагностическая сессия (нужна для §6 и §7)

Сразу после `81` поднимается сессия:

```
-> 83 03 00 FF 00 FF 00   AccessTimingParameter (subfn 03 = задать значения:
                          P2min=00 P2max=FF P3min=00 P3max=FF P4min=00)
-> 10 81                  StartDiagnosticSession, сессия 0x81 (НЕ 0x85!)
   ... цикл ...
-> 20                     StopDiagnosticSession   при выходе
-> 82                     StopCommunication
```

Ответы на `83` и `10 81` оба тула **не проверяют** — шлют и идут дальше.

**Отдельной команды «войти в режим тестирования» у 5AM нет**: `31 21`, `30 7E 04` и
`30 <lid> 07/00` — обычные сервисы внутри этой сессии, а сервис `0x10` встречается только
в bring-up и при смене скорости из §4.2. «Режим тестирования» — соглашение интерфейса, а не состояние ECU: полинг параметров
во время теста не прерывается.

Логгер поднимает эту сессию **лениво — перед первой командой с вкладки Testing**
(`KWP2000Session.enter_test_mode`), потому что `21 <rli>` работает и в дефолтной сессии.

### 4.2 Скорость сеанса

Init ECU слышит только на 10400. Когда связь поднята, `10 85 <код>` переводит её на другую
скорость:

| код | бод | | код | бод |
|---|---|---|---|---|
| 1 | 9600 | | 4 | 57600 |
| 2 | 19200 | | 5 | 115200 |
| 3 | 38400 | | 6 | NRC 0x10 |
| | | | 7 | 38400 |

```
-> 10 85 03               StartDiagnosticSession 0x85, код скорости 3
<- 50 85                  ещё на 10400; ECU меняет скорость после этого ответа
   (тестер перенастраивает порт, ждёт ~P3min)
-> 3E                     TesterPresent на 38400 — любой ответ подтверждает скорость
<- 7E
```

- **Условия.** ECU соглашается только при заглушённом двигателе, стоящем мотоцикле и питании
  10,0…15,5 В; иначе отвечает `7F 10 22` (conditionsNotCorrect) и остаётся на прежней
  скорости. Установленная скорость держится весь сеанс — пуск двигателя её не сбрасывает, —
  но новый init снова идёт на 10400.
- **`10 81` её сбрасывает.** Стандартная диагностическая сессия (§4.1) работает на 10400,
  поэтому её подъём для команды с вкладки Testing возвращает связь на 10400.
- **Делитель.** UART ECU делит 781250 на целое (`781250 / бод − 1`), поэтому верхние скорости
  уходят от номинала: 19200 и 38400 ≈ +1,7 %, 57600 ≈ +4,3 %, 115200 ≈ +13 % — больше, чем
  выдерживает UART. Логгер предлагает 10400 (без смены), 19200, 38400 и 57600
  (экспериментальная).
- **Выигрыш.** Запрос — 6 байт туда и 8 обратно: 13,5 мс на линии при 10400, 3,6 мс при 38400.
  Большая часть запроса — собственная задержка ответа ECU, и от скорости она не зависит.
- Есть и вторая форма запроса (19200/31250/38400/62500 без условий), но ей нужен сначала
  `10 84 04`, после чего `21 <rli>` отвечает лишь на несколько идентификаторов — для live-данных
  не годится.

На мотоцикле ещё не подтверждено.

Negative response: `7F <SID> <NRC>` (0x10 generalReject, 0x11 serviceNotSupported,
0x12 subFunctionNotSupported, 0x22 conditionsNotCorrect, 0x31 requestOutOfRange, …).

## 5. Live-параметры — сервис 0x21 (ReadDataByLocalIdentifier)

Каждое измерение — **отдельный** запрос; блочного «read all» нет.

```
-> 21 <rli>
<- 61 <rli> <value...>        байты значения = DATA ответа с offset 2, big-endian, 1..3 байта
```

IAW 5AM отвечает на все `rli` в **0x30..0x7F** (79 живых идентификаторов на тестовом моте). Длина
значения своя у каждого rli, берётся из длины кадра. Имена и формулы сверены с захватом
(RPM ~1500 на ХХ, впрыск 4–29 мс, АКБ ~12–14 В, лямбды осциллируют):

| rli  | канал           | формула   | ед.  | примечание |
|------|-----------------|-----------|------|------------|
| 0x30 | RPM             | raw       | об/мин | ХХ ~1500, раскрутка до ~4500 |
| 0x32 | Темп. воздуха   | raw − 40  | °C   | ~окружающая |
| 0x33 | Темп. ОЖ        | raw − 40  | °C   | растёт при прогреве |
| 0x34 | Дроссель        | raw / 10  | °    | ХХ ~1.8° |
| 0x35 | Опережение (защёлк.)| raw / 10 | ° | signed; 20.0° на прогретом ХХ; при остановленном моторе замирает на последнем значении |
| 0x37 | Опережение (живое)| raw / 10 | °  | signed; на ходу то же число; ровно 8.0°, пока мотор не крутится |
| 0x39 | Впрыск          | raw / 1000| мс   | 0 на заглушенном, 8.6 мс на прокрутке, ~1.4 мс на прогретом ХХ |
| 0x3A | Целевые ХХ      | raw       | об/мин | целевые обороты ХХ от темп.: 1571 холодный → 1401 прогретый (совпало с картой ECU) |
| 0x3C | АКБ             | raw / 10  | В    | 11.9–14.1 В |
| 0x45 | Lambda F (перед)| raw       | мВ   | осциллирует (closed loop) |
| 0x47 | Интегратор лямбды F | raw / 10 | % | signed 16-бит, −18…+25 % |
| 0x4B | Фаза регулятора F | raw     | —    | 1 заморожен, 2 холодный датчик, 3/4 разомкнут, 5 замкнут (обедняет), 7 замкнут (обогащает) |
| 0x53 | Скорость        | raw       | км/ч | 0 на стоянке, 87 на отсечке 8384 об/мин на второй; rpm/скорость даёт передачу |
| 0x6A | Поправка дросселя (обвод ХХ) | raw / 10 | ° | воздух через шаговый ХХ в пересчёте на угол дросселя, прибавляется к 0x34; 0 в закрытой зоне, 0–2.9° вне её, падает по мере прикрытия шагового на прогреве |
| 0x6B | Шаговый ХХ (база) | raw     | шаг  | по температуре: 117 при 51 °C, 100 от 75 °C и выше |
| 0x6C | Шаговый ХХ (позиция) | raw  | шаг  | 0x6B + 0x6D; сумма точна в 83 % отсчётов и в пределах ±2 в 99 % |
| 0x6D | Шаговый ХХ (коррекция) | raw | шаг | signed; замкнутая поправка поверх 0x6B |

Цилиндры — **F/R (передний/задний)** по компоновке V-twin Moto Guzzi / Ducati / Moto Morini.
Ещё часть именованных каналов расшифровывается картой из `config/status_maps.json`: 0x49 — флаг
контура (0 разомкнут, 2 замкнут), 0x58 — режим подачи топлива (перечисление, не битовое поле: 0 стоп, 1 прокрутка, 2 работа, 3 замедление,
4 ускорение, 5 ХХ, 6–9 те же четыре с разрешённой отсечкой, 10 отсечка, 11 возврат подачи), 0x5C — зона
дросселя (1 закрыт, 4 промежуточно, 2 полностью открыт — границы от обученных упоров, с гистерезисом),
0x6E — флаг перегрева ОЖ (1 при 110 °C и выше, когда мотор проработал 10 с при исправном датчике
ОЖ, иначе 0), 0x70 — биты вентиляторов (0x01 вентилятор 2, 0x02 вентилятор 1, 0x04 оба, 0x08 запрос
вентилятора 2, 0x10 запрос вентилятора 1; запрос включается при пороге ОЖ из калибровки — 96 или
98 °C в зависимости от сборки — на работающем моторе, выход следует за ним; на Granpasso вывод вентилятора 2 занят
нагревателем лямбды, но его бит всё равно ставится, так что горячий мотор читается как 0x1F), 0x61 — флаг нейтрали, 0x76 — подножка, 0x78 —
сцепление. 0x54 / 0x55 — время накопления с компенсацией по напряжению, единица остаётся сырой.

Ещё пять идентификаторов несут состояние, а не измерение. **0x79 — killswitch** (1 = STOP), а
**0x7A — разрешение работы**, которое ECU вычисляет из входов: на мотоцикле оно следовало за killswitch с
инверсией, но сбрасывается и при опущенной подножке с включённой передачей, и при 0x77 = 0. **0x57 — состояние
двигателя**: 1 включение питания, 2 зажигание вкл. без вращения, 4 работает, 8 остановлен при
включённом зажигании, 0x40 зажигание выключено на ходу, 0x10 зажигание выключено, ожидание, 0x20
завершение с сохранением обученных данных. **0x62** — 0 при заглушенном, 4 на холостых,
2 выше холостых, с миганием между ними в полосе 1300–1700 об/мин при закрытом дросселе. **0x75** —
синхронизация по коленвалу: переходит в 1 в отсчёте включения стартера и держится всю работу мотора.

**38 из 79 отвечают константным нулём.** Образ обслуживает их тремя общими слотами — один на
двухбайтовый ноль, один на однобайтовый, один на два трёхбайтовых идентификатора, — то есть за ними
нет переменной и нет условия, которое их сдвинет: 0x31, 0x36, 0x38, 0x3B, 0x3F–0x44, 0x46, 0x48,
0x4A, 0x4C, 0x4D, 0x4E, 0x50–0x52, 0x56, 0x59–0x5B, 0x64–0x69, 0x6F, 0x71–0x73 и 0x7B–0x7F. Четыре
из этого списка, которые несли бы задний банк (0x46, 0x48, 0x4A, 0x4C), заглушены во всех образах
Moto Morini; ПО Ducati на том же ECU их подключает. Из 41 идентификатора со своим слотом два
постоянны во всех калибровках Granpasso — 0x74 (иммобилайзер выключен) и 0x63 (неиспользуемый
ШИМ-выход). Три зависят от сборки: 0x5D, 0x5E, 0x5F — обучаемые поправки топлива, живые там, где
обучение включено: 0x5D (режимы ХХ) и 0x5E (остальные режимы) — аддитивные, signed, в 1/500 мг на
впрыск; 0x5F — мультипликативная, signed, в промилле. 0x3D — CO-подстройка, шаг 0,04 мг (signed):
на closed-loop сборках неподвижна — команда прибора, которая её задаёт, отвергается, — на open-loop
её выставляют вручную прибором.
Ещё два — входы, которые ещё не видели в движении: 0x3E, аналоговый вход AN1
со значением 52, нижней точкой своей таблицы пересчёта, и 0x77, защёлка входа P3.6 — при 0 она
сбрасывает разрешение работы (0x7A), — всё время читавшаяся как 1.

Схема `config/params.json`: `{key, name, rli, fmt(2/0), offset, length, endian, signed, scale,
bias, recip, digits, default, group, map, map_type, dead}`. `dead` помечает идентификатор, который
обслуживается одним из этих общих нулевых слотов или который калибровка держит постоянным: запись
остаётся, но выбрать канал нельзя. `recip != 0` → `value = recip / raw` (период). `default` = выбран
для decoded-лога при старте (именованные вкл, неопознанные выкл). Worker опрашивает **только
выбранные** — меньше галок = выше poll rate.

## 6. Сбросы адаптаций (верифицировано для IAW 5AM)

Делать на заглушённом двигателе (kill-switch), зажигание включено.

| функция              | запрос      | positive-ответ | сервис |
|----------------------|-------------|----------------|--------|
| **Reset TPS** (Drosselklappe zurücksetzen) | `31 21` | `71 21` | StartRoutineByLocalId |
| **Reset самоадаптации** (Selbstadaption)   | `30 7E 04` | `70 7E` | IOControlByLocalId |

> IAW 5AM PF1C и PF2C используют одни и те же команды; у PF3C кнопки TPS reset нет. Другие семейства
> отличаются (IAW15RC — проприетарный байт 0x89; IAW7SM — `31 23` + таймер; MIUG3 — `31 21`, другой
> транспорт). Команда на проводе для 5AM — `31 21`, но 100% подтвердит только снифф K-Line.

## 7. Тесты актуаторов — сервис 0x30 (InputOutputControlByLocalIdentifier)

```
-> 30 <localid> 07        включить
-> 30 <localid> 00        выключить
<- 70 <localid> ...        positive
```

LocalID → актуатор по карте тестов IAW, командный байт 07/00.
У 2-цилиндровой Guzzi часть из них отсутствует — вернут NRC.

| id | актуатор | id | актуатор |
|----|----------|----|----------|
| 1  | Реле компрессора кондиционера | 10 | Форсунка цил. 3 |
| 2  | Катушка (передний цил.)        | 11 | Форсунка цил. 4 |
| 3  | Катушка (задний цил.)          | 12 | Реле вентилятора 1 |
| 4  | Шаговик ХХ                     | 13 | Реле вентилятора 2 |
| 5  | Реле бензонасоса               | 14 | Подогрев лямбды 1 |
| 6  | Тахометр                       | 15 | Подогрев лямбды 2 |
| 8  | Форсунка (передний цил.)       | 16 | Клапан адсорбера |
| 9  | Форсунка (задний цил.)         | 17 | Сигнальная лампа |
|    |                                | 18 | Лампа темп. ОЖ |

Таймера в ECU нет: выход остаётся включённым, пока его чем-нибудь не выключат. Логгер вместо
этого шлёт **кратковременный импульс**:
`07` отправляет команда, `00` — поллинг-цикл воркера по дедлайну. Длительность настраивается на
вкладке Testing (дефолт 5 с, кламп 0.5–30 с). Таймингом владеет плата, поэтому живые значения не
замирают на время теста, а выход гаснет даже если браузер закрыли или ушли из зоны Wi-Fi.

Часть карты подтверждена для 5AM отдельно: бензонасос=5, катушка R=3, форсунка R=9,
тахометр=6.

### 7.1 Результаты рутин — сервис 0x33

`33 <localid>` (RequestRoutineResultsByLocalIdentifier) подтверждает завершение рутины у тех
семейств, которые на неё отвечают (`31 21`, затем `33 21`). В работу с 5AM он не входит, поэтому
логгер пробует его best-effort после сброса TPS и показывает ответ:
отрицательный ответ здесь — ожидаемое поведение, а не ошибка.

## 8. Коды ошибок и идентификация

Статус-байт: `status & 0x0F` = тип неисправности (1/2/4/8), `status & 0x20` = сохранённая
(0 = текущая/новая), `status & 0x40` = индикатор. Решает именно бит 0x20 — более грубое
`status & 0x60 != 0` относит к сохранённым и индикатор тоже.

- **Read DTC** — `18 00 FF 00` (ReadDTCByStatus) → `58 <count> [hi lo status]×count`. Каждый DTC —
  2-байтовый код SAE J2012 (`P/C/B/U` + цифры) + байт статуса. Описания — из стандартных
  SAE-таблиц (en/es/fr/it).
- **Clear DTC** — `14 FF 00` (ClearDiagnosticInformation).
- **Идентификация ECU** — `1A 80` (ReadEcuIdentification) → поля по смещениям `config/ecu_id.json`:
  Drawing (0:11), Hardware (11:22), Omologation, Software, Tester, Date. Рендерится в
  размеченный `.txt` (Date = дата чтения), показывается в Firmware → Read и сохраняется
  рядом с дампом.

## 9. Чтение/запись прошивки

Программный путь ([`denandz/5am_util`](https://github.com/denandz/5am_util), собран под aarch64):
`10 85` StartDiagnosticSession → `27` SecurityAccess (seed/key) → смена baud → блочный transfer
(`34`/`36`) + checksum. Размер образа ровно **327680** байт (0x50000); запись другого размера
блокируется. Чтение ≈ 20 мин. ⚠ Запись рискует «окирпичить» ECU.

## 10. Статус-биты

Декодеры в `config/status_maps.json` (привязать к status-rli после опознания):

- **fuel_mode** (enum, 0x58): 0 стоп … 5 ХХ … 7 ХХ с разрешённой отсечкой … 10 отсечка,
  11 возврат подачи.
- **runstate** (enum, 0x57): 01 включение питания, 02 зажигание вкл., 04 работает, 08 остановлен,
  10 зажигание выкл., 20 завершение, 40 зажигание выкл. на ходу.
- **throttle_zone** (enum, 0x5C): 01 закрыт, 02 полностью открыт, 04 промежуточно.
- **fans** (биты, 0x70): 01 вентилятор 2, 02 вентилятор 1, 04 оба, 08 запрос вентилятора 2, 10 запрос вентилятора 1.
- **motor** (биты cut-off, 16-бит): 0001 Crank … 0040 Steady running … 0400 In cut-off …
  2000 Выход из cut-off (разгон).
- **tps_state** (биты): 01 min, 02 полностью открыт, 04 середина.
- **immobilizer** (enum): 0 stored, 1 virgin, 2 no-start, 3 universal code, 5 backdoor code,
  6 erroneous key, 8 no code.
- **sidestand / clutch / gear / onoff** (enum'ы).
