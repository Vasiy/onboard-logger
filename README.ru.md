# Onboard Logger

Автономный бортовой **K-Line логгер диагностики** для мотоцикла с ECU **Magneti Marelli
IAW 5AM (HW610)** на базе **NanoPi NEO3** (Ubuntu 24.04). После подачи питания плата поднимает
Wi-Fi точку доступа с mobile-first веб-интерфейсом, подключается к диагностической шине ECU,
показывает параметры в реальном времени и пишет лог в `/root/k-line/`.

🇬🇧 [English version](README.md) · 🔧 [Референс протокола](docs/PROTOCOL.ru.md) ·
🔍 [Что дали ПК-программы](docs/REVERSE.ru.md)

## Возможности

- **Wi-Fi в двух режимах** (взаимоисключающие, переключаются в Config):
  - *Точка доступа* `nano loger` (hostapd, WPA2) + DHCP-сервер — к ней подключаешься на мотоцикле.
    Авто-выбор наименее загруженного канала 2.4 ГГц, селектор `Auto`/1–13 + график занятости.
    Адрес маршрутизатора необязателен и пуст по умолчанию: точка никуда не маршрутизирует, поэтому
    клиентам сообщается, что шлюза по умолчанию нет.
  - *Клиент* — подключение к существующей сети (wpa_supplicant), адрес по DHCP или вручную.
    DHCP-сервер не поднимается. Если подключение не встало за 45 с, плата **возвращает свою точку
    доступа** и откатывает сохранённый режим — неверный пароль не может оставить её без эфира.
- Веб-сервер (FastAPI) на порту 80, доступен и по Wi-Fi, и по eth0.
- **Авто-подключение** к IAW 5AM по K-Line — KWP2000/ISO 14230, 10400 8N1, **fast или 5-baud slow
  init**. Зелёный `status_led` горит при устойчивой связи, мигает при поиске.
- **Live-параметры** читаются поканально (`0x21 <rli>`); **верифицированная карта 5AM** (RPM, темп.
  ОЖ/воздуха, дроссель, впрыск, АКБ, lambda F/R, fuel trim F/R, CO/duty) плюс все прочие читаемые
  `rli` как raw. Опрашиваются **только выбранные** → меньше галок = выше poll rate.
- **Два потока логов** (независимые тумблеры): decoded-CSV параметров + сырой лог кадров; автостарт
  при коннекте, не пишет без связи, авто-zip при закрытии.
- **Full parameter scan** — перебор `0x00..0xFF` (адресный / оба framing), таймер авто-стопа с
  прогрессом первого прохода; пишет `scan-*.ndjson` + широкий `scan-*.csv`. Инструмент для карты
  новых rli. У каждого зонда своя метка времени, плюс **метки событий** (подножка / сцепление /
  передача / kill-switch / свой текст, с задержкой, чтобы успеть дойти до переключателя): щёлкнул
  тумблером, поставил метку — rli, который меняется вокруг неё, и есть этот статус-канал.
- **Веб-интерфейс** (табы):
  - *Logger* — тумблеры decoded/raw/scan, live-значения + 3-сек спарклайны, poll rate, именованные
    каналы сверху, неопознанные rli свёрнуты. Зелёный баннер показывает идентичность подключённого ECU.
    Переключатель **показ / выбор**: «показ» оставляет только отмеченные каналы и раскладывает их
    плитками с крупным числом (для взгляда на руле), «выбор» — прежний список с чекбоксами; режим
    запоминается в браузере.
  - *Firmware* — чтение/запись образа через [`denandz/5am_util`](https://github.com/denandz/5am_util);
    в блоке Read показывается live-описание ECU (сохраняется в GuzziDiag-совместимый `.txt` при чтении);
    upload/download/diff/delete `.bin` (+`.txt`), запись только точного размера (327680 Б).
  - *K-Line logs* — список с чекбоксами, download/delete и **Preview** нормированных графиков
    decoded-CSV (canvas, зум колесом / панорама, переключение серий, hover значений).
  - *Testing* — **чтение/стирание кодов ошибок** (SAE-декод, локализованные описания, *сохранённая
    или текущая* и тип неисправности из статус-байта), **сбросы адаптаций** (TPS `31 21` с
    прогресс-баром дросселя между кнопками, самоадаптация `30 7E 04`), **тесты актуаторов**
    (`30 <id> 07/00`, длительность импульса 0.5–30 с, кнопка Stop; таймингом владеет плата, поэтому
    выход погаснет, даже если браузер пропал), **справочник профилей ECU** (65 моделей Guzzi → ECU →
    протокол) и таблицы статус-битов. Диагностическая сессия, которую поднимают ПК-тулы
    (`83 03 00 FF 00 FF 00` + `10 81`), включается лениво при первом тесте — путь логгера не меняется.
  - *Config* — режим Wi-Fi и учётные данные, блок Network (hostname, адреса, DHCP-сервер или
    DHCP-клиент), скорость шины (Auto/фикс.), init (fast/slow), язык и **часы**: батарейного RTC у
    платы нет, поэтому первый браузер, открывший интерфейс после включения, задаёт дату, время и
    таймзону (один раз за включение и только при расхождении больше 2 с; отключается чекбоксом),
    плюс кнопка ручной синхронизации, и **оформление** (авто / светлое / тёмное — выбор устройства,
    не платы). Не-сетевые настройки сохраняются сразу при изменении, сетевые — по кнопке
    «Сохранить и применить», а счётчик несохранённых сетевых полей едет с прокруткой.
- **8 языков** (En по умолч., De, Es, Fr, It, Nl, Bg, Ru).
- **Полевые мелочи**: обрыв Wi-Fi с платой виден сразу (значения гаснут, статус говорит «связь
  потеряна» — замерший снапшот не выдаёт себя за живой), подтверждения опасных действий —
  собственные диалоги с названием действия в кнопке, кнопки маркеров и актуаторов рассчитаны на
  перчатку, портрет и ландшафт разложены отдельно, интерфейс ставится на экран «Домой» как
  standalone-приложение.

## Железо

| Узел | Что |
|---|---|
| Плата | NanoPi NEO3 (RK3328), Ubuntu 24.04, kernel 6.6 |
| Wi-Fi | USB-донгл Ralink RT5370 (`rt2800usb`, AP-режим) |
| K-Line | USB KKL/FTDI-кабель (FT232R) → `/dev/kline`, Fiat 3-pin разъём |
| LED | `/sys/class/leds/status_led` |

K-Line = pin 16 OBD2. На разъёме ECU: 12 В = pins 4 и 17, GND = pins 10 и 34, K-Line = pin 16.
В кабеле трансивер класса L9637D — TXD FTDI напрямую к K-Line не подключается.

## Установка (на плате)

```bash
git clone <repo> onboard-logger
cd onboard-logger
sudo ./install.sh
```

`install.sh` ставит `hostapd dnsmasq python3-venv iw rfkill`, разворачивает приложение в
`/opt/onboard-logger` (venv), кладёт udev-правило `/dev/kline`, выводит `wlan0` из-под
NetworkManager, копирует конфиг в `/etc/onboard-logger/`, создаёт `/root/k-line` и включает сервис
`onboard-logger.service`.

Веб-интерфейс: `http://192.168.5.1/` (и по eth0 при отладке). Проверка —
`systemctl status onboard-logger` / `journalctl -u onboard-logger -f`.

## Конфигурация

`config/config.default.json` — значения по умолчанию, рабочая копия — `/etc/onboard-logger/config.json`
(они сливаются, поэтому новые ключи появляются после обновления). Почти всё правится на вкладке
Config; полезно знать эти ключи:

| ключ | смысл |
|---|---|
| `wifi.mode` | `ap` (раздавать сеть) или `client` (подключаться к сети) |
| `wifi.ssid` / `password` / `channel` / `auto_channel` / `country` | собственная точка доступа |
| `wifi.client.ssid` / `password` | сеть, к которой подключаемся |
| `wifi.client.ipv4` | `dhcp` или `static` |
| `wifi.client.ip` / `prefix` / `gateway` / `dns` | ручной адрес (`dns` только в конфиге, в UI его нет) |
| `network.ap_ip` / `prefix` | адрес точки доступа; `network.gateway` необязателен, пусто = клиенты без маршрута по умолчанию |
| `dhcp.*` | DHCP-**сервер**, только в режиме AP |
| `kline.port` / `baud` / `echo` / `init` | шина K-Line (`baud: "auto"` перебирает 10400/9600/15625/19200) |
| `testing.pulse_ms` | длительность импульса актуатора, 500…30000 |
| `testing.session_init` | `false` — не поднимать сессию `83` + `10 81` перед тестами |
| `system.auto_time_sync` | брать часы у первого веб-клиента после включения (по умолчанию `true`) |
| `log_dir` / `firmware_dir` / `firmware_size` / `locale` | пути, контроль размера прошивки, язык UI |

## Протокол (кратко)

- Кадр `[0x80|len] [0x10] [0xF1] [DATA…] [CS]`, `CS = Σ & 0xFF`; короткий `[len] [DATA…] [CS]`.
- Init: fast (BREAK 25/25 мс → `81`) или 5-baud slow (адрес `0x33` → `55 KW1 KW2` handshake).
- Live-данные поканально: `21 <rli>` → `61 <rli> <value>` (значение с offset 2, big-endian);
  keep-alive `3E` каждые 3 с, `82` при выходе. Для live `10 85`/`1A` не нужны.
- Сбросы адаптаций (5AM): **TPS** `31 21`, **самоадаптация** `30 7E 04`. Актуаторы: `30 <id> 07/00`.
- Тесты и сбросы работают внутри сессии, которую поднимают оба ПК-тула: `81` → `83 03 00 FF 00 FF 00`
  → `10 81` (сессия **0x81**, не 0x85), закрытие `20` + `82`. Отдельного «режима тестирования» нет.

Полные детали, таблицы параметров/актуаторов/DTC и источники реверса — в
**[docs/PROTOCOL.ru.md](docs/PROTOCOL.ru.md)**. `config/params.json` держит live-карту (per-parameter);
правь его, чтобы именовать/масштабировать новые rli из скана — без изменения кода.

## Разработка / тесты

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
for f in tests/*.py; do python "$f"; done      # оффлайн-тесты (без железа и радио)
uvicorn app.main:app --reload --port 8000     # локальный прогон UI (без AP/K-Line)
```

На dev-хосте без sysfs/systemctl/K-Line привилегированные действия деградируют в no-op —
приложение не падает.
